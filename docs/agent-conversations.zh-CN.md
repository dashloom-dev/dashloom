# Agent 对话

Dashloom 会把相关问题保存在工作空间隔离的对话线程中，让用户可以连续追问，而不会丢失业务语境。进入 **Agent**，选择五类专用分析师之一，再选择整个产品组合或某个真实产品，输入决策问题，然后在为该回答创建的对话中继续提问。

Agent 清单会根据交互分析使用的同一个 14 天窗口，分别计算每位分析师的准备度。Revenue Analyst 只能由收入指标、商业领域的 Custom 指标或匹配的竞品指标启用；SEO 与 Operations 也使用各自的数据契约。页面会在调用模型前显示匹配数据点数量和最新日期，API 还会再次校验，避免过期页面或直接请求生成没有相应证据的分析。模型对比使用相同的准备度策略。

## 上下文如何工作

- 对话创建后固定使用最初选择的分析师。
- 对话也会固定使用创建时选择的产品范围。直接调用 API 不能把单产品线程扩大到整个工作空间，也不能换成另一个产品。
- 单产品准备度、自有指标、关联竞品证据、经营目标、健康分和 Growth Mission 都会先在服务端完成过滤，再进入证据包。
- 如果对应产品后来被删除，线程会停止接受新分析，而不会悄悄扩大为整个工作空间。
- 每次提问都会重新构建当前的指标、竞品、数据新鲜度、产品健康分、竞品周期趋势和跨信号共同变化证据。
- 系统最多保留四次成功分析，并压缩为有长度限制的问题、摘要和建议动作。
- 历史原始指标和引用 ID 不会被复制到新一轮上下文。
- 历史文本一律视为不可信数据，不能修改系统规则。
- 新回答中的每条重要结论，都必须引用本次重新冻结的证据 ID。
- 跨信号证据只表示共同变化，不代表因果关系。基于它给出的解释必须明确标记为“假设”，并保留 relationship 证据 ID。
- 竞品趋势使用与自有指标相同的周期聚合规则，但采集方法仍可能不同，解释时必须披露这一限制。
- 交互分析比较最近 7 天与此前 7 天；定时日报、周报和月报分别使用匹配的 1 天、7 天和 30 天对比窗口。

点击任一回答下的 **Inspect frozen evidence** 可以核对本次输入和通过校验的引用。可以在对话列表中归档已经完成的线程；归档只会从活动列表隐藏，不会删除可审计的运行记录。

## 如何选择范围

需要进行产品组合资源分配、跨产品排序或经营简报时，选择 **All products**。排查单个产品的异常、收入目标、SEO 机会或准备产品/客户更新时，选择具体产品。由 Signal Radar 发起的分析会自动选择并锁定信号所属的产品。

## 适合的追问

- “和上一轮相比，哪些风险发生了变化？”
- “把可信度最高的机会整理成三步实验。”
- “对比收入和 SEO 变化，但不要混合不同币种。”

Agent 的回答不能代替会计、法律或事故处置授权。涉及重要操作时，请回到引用的原始证据核对。
