# Agent Action Center

Dashloom Agent 不只是生成一段分析文字。交互分析、告警以及每日、每周、每月报告中的每条通过契约校验的 Finding，都会进入 **Agent actions**，成为带证据链接的行动项。

## 行动如何生成

行动会冻结 Finding 标题、解释、下一步建议、产品范围、严重程度、置信度、数据引用和来源分析运行。Dashloom 将产品、标题和建议行动标准化后计算 SHA-256 指纹；完全相同的重复建议会更新原行动并增加出现次数，而不是生成另一张卡片。

系统还保存 Append-only occurrence 台账，并以分析运行和 Finding 序号建立唯一约束，因此重试和历史回填不会虚增重复次数。如果行动物化失败，原分析仍然可用，并记录可重试的修复错误码；**Import recent findings** 可以安全地分批重试最多 100 条历史分析。契约不兼容的旧分析会被单独标记，不会无限重试。

Agent 输出只能引用本次分析保存的数据快照中存在的产品 ID 和证据 ID。未知产品、虚构引用、未标注的因果结论，以及没有披露的数据截断都会在保存 Finding 与行动前被拒绝。

## 状态流程

```text
suggested → planned → in progress → done
    └──────────────→ dismissed
done → in progress
dismissed → planned
```

工作空间 Owner、Admin 和 Member 可以把行动分配给当前成员、设置 UTC 截止日期、完成、重新打开，或填写原因后驳回；Viewer 只有只读权限。每次更新都使用 Compare-and-set 防止覆盖并发修改，并写入工作空间审计事件。

每日、每周、每月和手动 Agent 报告会带上五条最高优先级未完成行动，并显示状态、重复次数和 UTC 截止日期。如果完全相同的建议在完成后再次出现，Dashloom 会把它重新设为 **suggested**；用户主动驳回的建议会保持 dismissed，直到成员重新规划。

## 行动结果复盘

当一条产品级行动进入 **done**，Dashloom 会从来源 Finding 中解析指标和产品，再沿引用证据回到冻结的分析运行，把同一数据源最新的日指标保存为不可变的完成基线。流量型和比率型指标使用最近一个完整 UTC 日，避免拿当天不完整数据与后续完整日比较；MRR 等存量指标可以使用完成当日。工作空间导出会包含每一次完成周期及其测量结果。

后续日期的新指标进入系统后，定时维护任务和 **Refresh outcomes** 按钮都会用新日指标与基线比较。只有具备明确经营方向的指标才会判断为改善或回落；方向取决于上下文的指标只显示“发生变化”或“基本不变”。基线为零时不会生成误导性的百分比。

这是一种时间顺序复盘，不是实验。每个结果都会明确说明“完成后的变化不能证明由该行动导致”。没有产品级指标引用的建议仍会以证据不足显示，而不会被静默打分。行动重新打开并再次完成时会生成新的复盘周期，不覆盖原结果。

Action Center 是决策辅助工具，不是自动执行器。它不会部署代码、修改基础设施、花费资金、联系客户、执行退款或修改已连接 Provider。进行重要操作前必须检查链接中的冻结证据。
