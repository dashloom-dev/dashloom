# 连接器账号生命周期

Dashloom 会把每个提供方账号隔离在所属工作空间内，并支持同一个提供方配置多个账号。进入 **Data sources**，可以查看每个账号的健康状态、上次验证时间和有效产品映射数量。

## 连接或轮换凭据

使用 **Data sources** 中对应提供方的表单。Dashloom 会先向真实提供方验证凭据，验证成功后才把账号标记为已连接。再次提交同一个提供方账号会替换加密凭据，同时保留原有账号身份；这就是常规的密钥轮换路径。

请按照教程创建新的最小只读权限凭据。Dashloom 验证新凭据成功后，再到提供方控制台撤销旧凭据。

## 断开账号

Owner 和 Admin 可以在 Account Control 中选择 **Disconnect**。Dashloom 会立即：

1. 将连接器账号标记为 disabled，使同步器不再选择它；
2. 永久删除已保存的加密凭据；
3. 停用该账号拥有的所有产品映射；
4. 写入不包含凭据的审计事件。

历史聚合指标会保留，仍可用于历史报告和周期对比。连接器资源也会作为不含密钥的元数据保留，以便解释历史记录。重新连接并映射账号不会静默删除旧证据。

Dashloom 无法代替用户在其他提供方内部撤销 API Key。断开以后，还应进入 Cloudflare、Stripe、GitHub 或对应提供方的控制台撤销原始凭据。如果彻底停止使用 Google OAuth，还应在 Google 账号中移除 Dashloom 授权。

已停用账号不会继续计入提供方目录的已配置或健康数量。账号控制视图及读取接口不会返回加密凭据或外部账号标识。

## 诊断与修复

Account Control 会把账号状态、有效映射数量和最近一次同步结果组合为一条诊断。当连接需要处理时，页面会展示适合该提供方的修复清单：轮换或重新连接凭据、检查文档要求的只读权限和资源范围、在映射缺失时重新关联产品，然后执行手动同步并确认已经写入新证据。

浏览器只会收到稳定的同步错误代码；原始提供方响应和已保存凭据不会进入生命周期视图。
