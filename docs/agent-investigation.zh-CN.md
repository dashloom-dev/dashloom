# Agent 受控证据调查

Agent 在生成最终分析前，可以自主决定是否补查已导入的页面或查询词指标。此功能默认用于有指标证据的运行；仅含图片的分析保持原有流程。

模型对比继续使用同一份固定证据，不启用自主补查，以保持不同服务商之间的比较公平，并避免并发修改共享快照。

## 执行流程

1. 按原有权限和专家指标范围生成初始证据。
2. 模型返回严格校验的 JSON 决策：结束调查，或调用 `inspect_breakdown`。
3. 服务端只允许查询初始证据中的产品。工具参数包括产品 ID、页面或查询词维度，以及可选的精确标签。
4. 工具沿用初始证据的比较时间段，最多读取 2,000 条明细，沿用确定性指标聚合，再向分析加入最多 40 条记录。
5. 下一轮决策可以查看新增证据。最多两轮决策；达到上限后直接进入原有的最终分析、引用校验和修复流程。

工具不访问网页、执行任意 SQL、运行代码或写入业务系统。页面 URL 只是数据库标签。页面与查询词不能凭标签推断联合关系，币种、数据源、工作空间与专家范围沿用现有规则。

## 限制与兼容性

- 调查阶段有 35 秒截止时间；模型请求可中止，已发出的数据库读取会等待返回，之后不再启动新一轮决策。该截止时间不包含后续最终分析。
- 每轮决策上下文最多 24,000 字符，工具输出最多 40 条，最多新增 80 条证据。
- 标准 OpenAI 请求发送 350 tokens 的输出限制；模型专用兼容接口保持原有请求格式，不保证相同的服务商输出硬上限。
- 无效决策、重复请求、调查超时，或服务商以 400/422 拒绝调查请求时，使用已经取得的证据继续最终分析。认证、限流、其他服务商故障和数据库错误会按原有失败流程处理。
- 取消请求会阻止后续查询和最终分析。数据库查询本身不提供强制中断保证。
- 不扩大比较窗口，不同步外部连接器，也不自动执行分析建议。

## 证据与记录

新增记录使用独立的 `investigation:` 引用 ID，避免覆盖初始快照。每次运行的 `evidenceJson.investigation` 保存参数、证据引用、截断标记、完成时间和停止原因；最终引用校验可以验证这些新增 ID。调查记录属于审计信息，模型仍只能引用真实指标证据。

明细读取和返回记录被截断时，最终分析必须披露覆盖不完整。补查使用相同日期窗口，但数据库读取发生在不同时间，并不构成跨查询的事务快照。

Community 将成功调查调用的 tokens 合并到运行用量。Cloud 每轮托管调用独立预留和结算额度，并使用运行 ID 加轮次作为幂等键；模型专用接口沿用常规输出额度预留。失败运行可能已发生模型费用，额度预留不等于服务商硬费用上限。

界面的执行轨迹显示调查阶段和完成的查询数。此版本没有持久化任务恢复、审批后续跑、文件系统或多 Agent 执行能力。

## 验证

`tests/agent-investigation.test.ts` 覆盖多轮证据传递、引用校验、越界与参数注入、重复请求、步数与记录限制、取消、截止时间、服务商兼容降级，以及输出限制透传。运行 `npm test` 与 `npm run typecheck` 验证所在版本。
