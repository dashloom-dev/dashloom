# Agent Signal Radar

Agent Signal Radar 是 Dashloom 的实时决策队列。它扫描真实产品已经保存的汇总数据，对比两个完整的七天周期，并在调用模型之前，把可能值得关注的变化排列出来。

## 雷达会显示什么

- 变化幅度至少达到 10% 的重要指标；
- 处于 `watch` 或 `risk` 状态的产品健康分；
- 偏离目标、有风险或缺少匹配数据的经营目标；
- 偏离计划、已经错过或证据不足的 Growth Mission；
- 同一产品中共同变化或相互背离的跨领域信号。

每条信号都保留产品、来源、指标、货币、最新数据日期和数据引用。不同货币不会合并。比较周期会排除尚未结束的当天，避免把不完整的流量型指标误判成下降。

## 确定性检测，按需调用 AI

雷达不会让 LLM 判断“变化是否发生”。指标聚合、变化百分比、目标进度、任务进度、健康分、专项 Agent 路由和优先级全部由 Dashloom 确定性计算。

点击 **Analyze signal** 后，才会明确调用最匹配且已经准备好的专项 Agent：

- 商业与收入信号交给 Revenue Analyst；
- 获客与搜索信号交给 SEO Growth Analyst；
- 发布与基础设施信号交给 Operations Analyst；
- 产品指标和跨领域信号交给 Portfolio Analyst。

Agent 会重新冻结一份有界的最新证据。回答必须引用雷达条目对应的当前证据，并把已观察变化和原因假设分开。如果首选专项 Agent 没有匹配数据，而 Portfolio Analyst 已准备好，Dashloom 会使用后者继续分析。

## 用真实数据启用雷达

1. 在 **Products** 中创建你实际运营的产品。
2. 在 **Data sources** 中映射支持的账号，或使用标准化数据写入 API。
3. 执行同步，并确认产品页面出现近期数据日期。
4. 当两个对比周期都有历史数据后，打开 **Signal radar**。
5. 深挖优先信号，把有证据的建议转成 Agent Action；适合量化时，再批准 Growth Mission。

空雷达也会给出真实原因：尚未连接产品、没有可比较序列，或者没有变化超过重要性阈值。Dashloom 不会向用户工作空间填充演示指标。

## 解读边界

雷达排序用于辅助确定优先级，并不证明业务影响。较小的基数也可能产生很大的百分比。跨信号共同变化不是因果关系；健康分是确定性的运营摘要；经营目标和 Growth Mission 则来自用户明确设置。采取行动前，应核对引用证据和实际业务背景。
